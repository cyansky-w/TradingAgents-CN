# 实盘平仓持仓选择设计

## 目标

在新增实盘成交记录时，用户选择“平仓”后不再手工输入平仓标的，而是先选择市场，再从该市场的当前持仓中选择需要平仓的持仓方向。选择后展示当前持仓数量，用户自行输入不超过该数量的部分或全部平仓数量。

## 范围

- 仅处理实盘成交记录，不修改模拟交易。
- 适用于 A 股、港股、美股和加密永续。
- 仅新增记录的平仓流程强制选择当前持仓。
- 开仓流程维持现有标的输入方式。
- 编辑历史记录时保留原记录字段；即使对应持仓已经全部关闭，也不能阻止用户打开和修改历史记录。
- 不新增后端接口，复用实盘持仓页面已经加载的 `positions` 数据。

## 数据来源与唯一标识

父页面将当前 `PortfolioPosition[]` 传入 `TradeRecordForm`。表单按用户选择的 `market` 过滤可平持仓，并只展示 `quantity > 0` 的项目。

同一标的可能同时存在多头和空头，因此选项不能只使用 `storage_key`。前端选择值使用以下组合标识：

```text
market + exchange + symbol + instrument_type + position_side
```

该标识只用于前端定位持仓；提交请求仍使用现有账本字段，不增加新的持仓 ID。

## 表单交互

### 开仓

选择“开仓”时维持现有交互：用户选择市场并输入标的，持仓方向由用户选择。

### 平仓

选择“平仓”后：

1. 用户先选择市场。
2. 表单显示 shadcn-vue `Select` 实现的“当前持仓”下拉框。
3. 下拉框仅列出该市场内可平的当前持仓。
4. 每个选项显示：`标的 · 交易所 · 多头/空头 · 当前数量`。
5. 选择持仓后自动回填 `exchange`、`symbol`、`instrument_type`、`quote_asset` 和 `position_side`。
6. 持仓方向在平仓模式下由所选持仓决定，不允许用户另行切换。
7. 选择框下方明确显示“当前持仓数量”。
8. 平仓数量不自动填写，保持为空，由用户输入部分或全部平仓数量。
9. 切换市场或重新选择持仓时清空平仓数量，避免沿用上一持仓的数量。

如果所选市场没有当前持仓，下拉框显示空状态“该市场暂无可平持仓”，保存按钮不能提交平仓记录。

## UI 结构

```text
┌────────────────────── 新增实盘记录 ──────────────────────┐
│ 记录类型 [ 成交 ▼ ]        市场 [ 加密货币 ▼ ]           │
│ 操作     (○ 开仓  ● 平仓)                                │
│                                                          │
│ 当前持仓 [ BTC/USDT:USDT · binance · 多头 · 0.004 ▼ ]   │
│            当前持仓数量：0.004 BTC                       │
│                                                          │
│ 持仓方向  多头（根据所选持仓自动确定）                    │
│ 平仓价格 [ 66012.2          ]                            │
│ 平仓数量 [                   ] BTC                       │
│            可输入范围：0.001 ～ 0.004                    │
│                                                          │
│ 时间     [ 2026-07-22 12:00:00 ]                         │
│ 原因     [                              ]                │
│                                          [ 保存记录 ]    │
└──────────────────────────────────────────────────────────┘
```

表单仍保持一行最多两个字段。“当前持仓”选择和持仓数量提示占满一整行，避免长标的、交易所和方向信息被压缩。

## 数据流

```text
实盘页面加载 positions
        ↓
positions 作为 props 传入 TradeRecordForm
        ↓
用户选择市场 + 平仓
        ↓
表单筛选该市场 quantity > 0 的持仓
        ↓
用户选择具体持仓方向
        ↓
自动回填资产字段并显示当前数量
        ↓
用户输入平仓价格和数量
        ↓
前端校验 → 现有 POST /api/real-trades/record
        ↓
后端账本回放继续执行最终持仓校验
```

## 校验规则

- 未选择当前持仓时不得提交平仓记录。
- 平仓数量必须大于零。
- 平仓数量不得超过选择时的当前持仓数量。
- 平仓数量继续遵守市场数量规则：A 股为 100 的倍数；港股、美股和加密永续使用现有资产数量规则。
- 加密永续选择持仓后重新加载交易所数量规则。
- 前端校验用于即时反馈；后端持仓回放仍是最终一致性校验，以防多个页面或并发记录导致持仓数量变化。
- 如果保存时后端返回可平数量不足，保留表单内容并提示用户刷新当前持仓后重试。

## 状态变化

- 从开仓切换到平仓：清空手工标的和数量，等待选择当前持仓。
- 从平仓切换到开仓：清空已选持仓引用，恢复市场对应的普通标的输入和方向选择。
- 平仓状态切换市场：清空已选持仓、自动回填字段和平仓数量。
- 重新选择持仓：重新回填资产字段并清空平仓数量。
- 父页面刷新持仓后，如果已选持仓仍存在，则更新展示的当前数量；如果已经不存在，则将选择标记为失效并禁止提交。

## 组件边界

- `RealTrading/index.vue`：继续负责加载和刷新 `positions`，并将其传给表单。
- `TradeRecordForm.vue`：负责按市场筛选持仓、选择持仓、回填字段和前端数量校验。
- `realTrades.ts`：复用现有 `PortfolioPosition` 类型，不新增请求模型字段。
- 后端：不新增接口或数据结构，继续使用现有平仓账本校验。

## 测试与验收

- 选择 A 股市场时，下拉框只显示 A 股当前持仓。
- 选择加密市场时，下拉框只显示加密永续当前持仓。
- 同一标的的多头和空头显示为两个独立选项。
- 选择持仓后正确回填市场相关字段和持仓方向。
- 选择后展示当前持仓数量，但平仓数量保持为空。
- 用户可以提交小于当前持仓的部分平仓数量。
- 输入超过当前持仓的数量时前端阻止提交并显示可平数量。
- 切换市场或持仓后旧的平仓数量被清空。
- 没有可平持仓时显示空状态并禁止提交。
- 开仓表单行为不受影响。
- 编辑历史平仓记录时，即使当前已无对应持仓，仍可正常打开表单。
- 后端拒绝并发情况下已经超过最新可平数量的请求，前端保留输入并提示刷新。
