# TradingAgents-CN 管理系统设计文档

---

## 1. 概述

TradingAgents-CN 是一个面向量化交易场景的 AI Agent 管理与应用平台。系统围绕 **AI Agent 编排**、**交易策略管理**、**盯盘与复盘** 三大核心场景，提供可配置的 Agent、提示词、工具、工作流，并结合 vnpy 等实盘/模拟交易后端，实现从策略信号生成到执行的全链路管理。

本文档详细定义各功能模块的数据模型与 WebUI 设计，作为前后端开发的基础依据。

---

## 2. 整体页面结构

侧边栏导航采用分组设计：

```
侧边栏:
├── 首页/Dashboard
├── 盯盘中心
├── 复盘中心
├── 候选池
├── 模拟交易
├── AI 助手 (Chat)
│
├── ── 管理中心 ──
│   ├── Agent 管理
│   ├── 工具管理
│   ├── 提示词管理
│   ├── 工作流管理
│   └── 策略管理
│
├── ── 系统设置 ──
│   ├── 模型配置
│   ├── 数据源
│   └── ...
└── 关于
```

管理中心下的 5 个页面共享统一的 **左右分栏布局**：左侧为资源列表（支持筛选/搜索），右侧为选中项的详情编辑面板。

## 3. 模块详细设计

### 3.1 Agent 管理

Agent 是 AI 执行单元，绑定系统提示词、工具集、模型配置，可被工作流或聊天直接调用。

#### 数据模型 (MongoDB 集合: `agents`)

```json
{
  "_id": ObjectId,
  "name": "市场分析师",
  "description": "分析市场整体走势、板块轮动、资金流向",

  "prompt_id": ObjectId,
  "tool_ids": [ObjectId],
  "model_config": {
    "provider": "deepseek",
    "model": "deepseek-chat",
    "temperature": 0.3,
    "max_tokens": 4096
  },
  "parameters": {
    "max_tool_calls": 10,
    "timeout": 300,
    "retry_on_failure": true
  },

  "tags": ["分析", "盯盘"],
  "is_chat": false,
  "is_system": true,
  "enabled": true,

  "usage_count": 0,
  "last_used_at": null,

  "created_at": datetime,
  "updated_at": datetime
}
```

#### WebUI 布局

```
┌── Agent 管理 [+ 新建] ──────────────────────────┐
│ 筛选: [标签▾] [状态▾] [搜索...]                   │

- “测试运行”按钮弹出对话框，输入测试文本，流式输出 Agent 执行结果。

#### 数据模型 (集合: `prompts`)

#### WebUI 布局

```
┌── 提示词管理 [+ 新建] ───────────────────────────┐
│ 筛选: [标签▾] [状态▾] [搜索...]                    │

**编辑器特性**:
- 双模式：代码模式（直接编辑）与预览模式（变量替换后的效果）。
- `{{变量}}` 自动高亮。
- 右侧显示被哪些 Agent 引用，防止误删。

### 3.4 工作流管理

编排多个 Agent 的串并行执行流程，支持定时触发与事件触发。

#### 数据模型

**工作流定义** (`workflows`):

```json
{
  "_id": ObjectId,
  "name": "复盘工作流",
  "trigger": {
    "type": "cron",
    "cron": "0 20 * * 1-5"
  },
  "input_variables": [
    {"name": "date", "type": "string", "default": "today"}
  ],
  "nodes": [
    {
      "id": "market_analyzer",
      "agent_id": ObjectId,
      "input_mapping": {"date": "{{date}}"},
      "position": {"x": 100, "y": 200}
    },
    {
      "id": "stock_analyzer",
      "agent_id": ObjectId,
      "input_mapping": {
        "symbol": "{{item.symbol}}",
        "market_report": "{{market_analyzer.output}}"
      },
      "loop_over": "input.symbols",
      "parallel": true
    }
  ],
  "edges": [
    {"from": "market_analyzer", "to": "stock_analyzer"}
  ],
  "settings": {
    "timeout": 3600,
    "on_failure": "notify",
    "retry_count": 1
  },
  "tags": ["复盘"],
  "enabled": true,
  "created_at": datetime,
  "updated_at": datetime
}
```

**运行实例** (`workflow_runs`):

```json
{

  "workflow_id": ObjectId,

│ └────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

可切换不同日期的复盘记录，支持手动触发复盘工作流。

## 4. 模块依赖与开发顺序

**第一层：基础设施（无依赖）**
- 工具管理 (Tool Registry)
- 提示词管理 (Prompt Registry)
- Agent 管理 (依赖 Tool + Prompt)

**第二层：工作流引擎**
- 工作流管理 (依赖 Agent)

**第三层：业务场景**
- 候选池管理 (数据模型简单，可提前)
- 策略管理 (元信息管理，vnpy-worker 后接)
- 盯盘中心 (依赖工作流)
- 复盘中心 (依赖工作流)

**第四层：vnpy 对接**
- vnpy-worker 独立开发，通过工具管理注册 RPC 工具。

## 5. 全局设计原则

- **配置驱动**：Agent、提示词、工具、工作流均可通过 UI 配置，减少硬编码。
- **状态可视化**：工具健康检查、工作流节点执行状态、策略回测进度等均提供实时反馈。
- **多标签叠加**：盯盘股票的状态支持同时拥有多种标签（实盘、模拟、观察等），用图标直观区分。
- **响应式布局**：列表/卡片视图可切换，适应不同数据量和使用习惯。
