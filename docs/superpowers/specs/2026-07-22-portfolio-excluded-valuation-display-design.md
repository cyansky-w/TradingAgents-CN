# 实盘持仓排除估值展示设计

## 目标

当单个实盘持仓因行情不可用而无法估值时，页面继续展示该持仓的基础信息，不因行情源故障隐藏持仓或中断整个组合估值。用户可以从汇总区域查看被排除标的及具体原因。

## 范围

- 仅修改实盘持仓接口和实盘持仓页面。
- 不修改模拟交易。
- 不修改行情源选择、重试或 API Key 配置。
- 不修改持仓数量、成本、做多/做空计算规则。
- 保留现有换汇失败的“未换算”状态，并与行情不可用区分。

## 后端数据设计

`PortfolioService.get_positions` 在行情网关失败时仍生成一个持仓展示项。该项保留：

- `storage_key`
- `market`
- `exchange`
- `symbol`
- `instrument_type`
- `position_side`
- `quote_asset`
- `quantity`
- `average_entry_price`
- `cost_value`
- `realized_pnl`

行情相关及估值相关字段设为空：

- `mark_price`
- `market_value`
- `unrealized_pnl`
- `base_market_value`
- `base_cost_value`
- `base_unrealized_pnl`
- `weight_percent`

展示项增加：

- `quote_unavailable: true`
- `quote_error: <错误文本>`

同一持仓仍加入 `excluded`，明细至少包含 `storage_key`、标的身份、持仓方向、`scope: quote` 和错误文本。组合市值、盈亏与权重只统计成功估值的持仓。

## 前端交互

### 当前持仓表

行情不可用的持仓继续显示一行：

- 标的、交易所、品种、方向、数量和持仓均价正常显示。
- 标记价、原币市值、基准币市值、盈亏和权重显示 `-`。
- 状态列显示醒目的“行情不可用”。
- 不显示“行情过期”或“未换算”，避免状态歧义。

### 排除估值明细

汇总卡中的“排除估值”数字改为按钮式可点击指标：

- 数量为 0 时禁用点击。
- 数量大于 0 时点击打开轻量弹层。
- 弹层逐项显示标的、方向、市场/交易所及失败原因。
- 弹层只读，不提供删除、重试或配置入口。

`dashboard.excluded` 作为弹层的数据源，确保同时覆盖行情失败、换汇失败和已实现盈亏无法计算等排除原因。缺失字段使用 `-` 展示。

## 错误处理

- 单个行情请求失败不能使 `/positions` 或 `/dashboard` 返回 500。
- 错误文本仅用于用户解释，不影响其他持仓计算。
- 失败持仓不参与组合总市值、总盈亏和权重分母。
- 页面在排除明细字段不完整时仍可正常渲染。

## 测试

后端测试：

- 美股空头行情失败时接口返回该持仓展示项和一条 excluded 明细。
- 失败持仓的估值字段为空且不进入组合汇总。
- 其他可估值持仓仍正常返回。

前端测试：

- 行情不可用持仓仍出现在持仓表。
- 估值字段显示 `-`，状态显示“行情不可用”。
- 点击非零“排除估值”指标可查看原因。
- 排除数量为 0 时指标不可点击。

## 验收标准

在美股行情源不可用且已存在 AAPL 空头持仓时：

1. 实盘持仓页面正常加载，相关接口返回 200。
2. 当前持仓表显示 AAPL 空头行。
3. AAPL 的市值、盈亏和权重显示 `-`。
4. AAPL 状态显示“行情不可用”。
5. 汇总卡显示“排除估值 1”，点击后能看到 AAPL 和行情失败原因。
6. 其他持仓和组合汇总不受影响。
