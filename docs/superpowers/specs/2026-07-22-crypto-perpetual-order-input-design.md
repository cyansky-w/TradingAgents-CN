# 加密永续合约下单输入设计

## 目标

将 USDT 本位永续合约的订单名义金额、初始保证金和杠杆纳入开仓成本计算，而非仅作为合约元数据。用户可按数量、订单名义金额或初始保证金三种方式开仓，系统自动换算其余数值。

## 范围

- 首版只支持 `crypto_linear_perpetual`（USDT 本位永续）。
- 仅对开仓记录生效；平仓继续以数量和价格记录。
- 做多和做空使用相同的绝对值换算；方向仅影响后续盈亏方向。
- 不实现自动止损、爆仓、资金费结算或全仓/逐仓风险隔离。
- 不修改模拟交易。

## 计算模型

设价格为 `P`（USDT / 标的币），数量为 `Q`（标的币），杠杆为 `L`，订单名义金额为 `N`（USDT），初始保证金为 `M`（USDT）：

```text
N = Q × P
M = N ÷ L
Q = N ÷ P
N = M × L
```

所有计算使用 Decimal；展示与保存前按交易所数量规则和价格精度处理。杠杆必须大于 0，价格必须大于 0，主输入金额必须大于 0。

## 前端交互

加密永续开仓表单新增“下单计算方式”单选：

1. 按数量：输入数量、价格、杠杆；自动显示订单金额和初始保证金。
2. 按订单金额：输入订单金额、价格、杠杆；自动计算数量和初始保证金。
3. 按初始保证金：输入初始保证金、价格、杠杆；自动计算订单金额和数量。

当前主输入字段可编辑；自动计算字段只读。切换方式时保留可推导的数值。该“下单计算方式”与保证金模式（全仓/逐仓）无关；首版从表单中移除全仓/逐仓选择，避免暗示未实现的风险模型。

## 数据与持仓

后端接收并保存最终的 `quantity`、`price`、`leverage`、`initial_margin` 和 `order_notional`。账本和持仓成本以 `order_notional` 为成交名义金额，开仓初始保证金是该订单的保证金占用展示数据，不替代名义成本。费用逻辑保持现有规则。

已有记录缺失 `order_notional` 时按 `quantity × price` 回退计算；缺失 `initial_margin` 时不反推或显示为空。

## 验收

以 BTC/USDT:USDT、价格 100,000、杠杆 10x 为例：

- 数量 0.01 自动得到订单金额 1,000、初始保证金 100。
- 订单金额 1,000 自动得到数量 0.01、初始保证金 100。
- 初始保证金 100 自动得到订单金额 1,000、数量 0.01。
- 三种方式提交后保存的最终数量、价格、订单金额和初始保证金一致。
- 多头与空头得到相同的数量、订单金额和初始保证金绝对值。
